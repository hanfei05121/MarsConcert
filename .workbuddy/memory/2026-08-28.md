# 2026-08-28

## 排查并修复 electron-builder 打包失败（winCodeSign 符号链接权限）

**症状**：`npm run pack` 报错：解压 winCodeSign-2.6.0.7z 时 "Cannot create symbolic link / 客户端没有所需的特权"
（darwin/10.12/lib/libcrypto.dylib、libssl.dylib），重试 3 次后失败。

**根因链**（已读 electron-builder 25.1.8 源码 + 反查 app-builder 二进制字符串确认）：
- 改 exe 图标/版本信息的是 app-builder 的 `rcedit` 命令（winPackager.js signAndEditResources → executeAppBuilder(["rcedit",...])）。
- app-builder 的 rcedit 在执行前会先 `download.DownloadWinCodeSign`（内部字符串确认），下载后用 7za 解压到
  `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\<随机数字目录>`，包内含 macOS 用的 dylib 符号链接。
- 当前用户无 SeCreateSymbolicLinkPrivilege（未开开发者模式、非管理员）→ 7za exit 2 → 整个 rcedit 步骤失败，
  于是 exe 的图标/版本信息从未被写入 → 应用 exe 一直是 Electron 默认图标（ProductName 还是 "Electron"）。
- Setup 安装包图标正常，是因为 NSIS 编译安装程序时直接把 build/icon.ico 写进安装包 PE（installerIcon），不经 rcedit。
- 验证：8/25 成功构建的「火星演唱会 Setup 1.0.0.exe」内嵌的 exe 也是 Electron 默认图标（用 scripts/peicon.py 解析确认），
  说明这个坑从最早构建就一直存在。

**修复**：
- 手动预置缓存：把 winCodeSign 7z 解压到 `C:\Users\han\AppData\Local\electron-builder\Cache\winCodeSign\winCodeSign-2.6.0\`
  （忽略 2 个 dylib 符号链接错误，Windows 用不到 darwin/linux 目录），app-builder 检测到目录存在即跳过下载解压。
- 用 app-builder rcedit 直接对 release/win-unpacked/火星演唱会.exe 验证：4.2s 成功，图标变为 6 尺寸
  （字节数与 build/icon.ico 完全一致）、ProductName/InternalName=火星演唱会。
- 待用户重跑 `npm run pack` 即可生成带正确图标的安装包。

**长期建议**：开启 Windows「开发者模式」（设置→系统→开发者选项），或管理员运行终端，彻底避免符号链接权限问题。

**新工具**：scripts/peicon.py —— 解析 PE 的 RT_GROUP_ICON/RT_ICON 资源，可用来验证 exe/安装包图标是否被正确替换。
用法：`python scripts/peicon.py <exe路径>`。
