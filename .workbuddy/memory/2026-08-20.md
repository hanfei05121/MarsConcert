## 启动报错修复（karaoke-desktop）

### 问题 1：构建报错 `scanLibrary is not exported by database.ts`
- 根因：`src/main/index.ts` 从 `'./database'` 导入 `scanLibrary`，但该函数定义在 `src/main/scanner.ts`。

### 问题 2：运行时报错 `ERR_PACKAGE_PATH_NOT_EXPORTED`（sql.js/package.json）
- 根因：`database.ts` 用 `require.resolve('sql.js/package.json')` 定位 wasm，但 sql.js@1.14.2 的 `package.json` 的 `exports` 只暴露 `.` 和 `./dist/*`，未暴露 `./package.json`。
- 修复：`database.ts` 改为 `require.resolve('sql.js/dist/sql-wasm.wasm')`（`./dist/*` 子路径已开放）。同时移除了不再使用的 `dirname` 导入。
- 素材库约定：`<songLibPath>/<歌名>/orig.mp4 [accomp.mp4] [歌名.lrc]`，缺 orig.mp4 但有 lrc 也可入库。

### 备注
- `npm run dev` 运行时报错来自 `dist/main/index.js`（electron-vite 先编译 main 到 dist 再运行），改源码后需重新构建才生效。

## 播放时无法切屏/控制台点不动（双屏置顶陷阱）

### 根因
`src/main/windows.ts` 的 `createPlayerWindow()` 同时设了三个致命项：
1. `alwaysOnTop: true` → 系统级置顶（WS_EX_TOPMOST），压住所有窗口（含控制台与其它软件），点控制台也浮不到前面。
2. `fullscreen: true` → Windows 独占式全屏，难切走。
3. `win.focus()` → 一播放就抢走键鼠焦点，控制台失焦"点不动"。
三者叠加导致只能关副屏（销毁播放窗）才能夺回控制权。

### 修复
- `windows.ts`：去掉 `alwaysOnTop` 与 `win.focus()`，把 `fullscreen:true` 改为 `fullscreen:false` + 无边框(`frame:false`) + `setBounds` 铺满副屏，做"视觉全屏"，不再独占/置顶。
- 新增 Esc 逃生口：`types.ts`(IPC.PLAYER_ESCAPE + KaraokeApi.escape)、`preload`(escape)、`index.ts`(handler: 最小化播放窗并 focus 控制台)、`player/App.vue`(Esc 监听调 escape)。
- 构建验证：`npm run build` 通过（注意：首次 build 会因 safe-delete 回收站 shim 失败 `emptyDir`，先 `rm -rf dist` 再 build 即可；非代码问题）。

## 音频比歌词慢 / 歌词对不上（LRC 与视频时间轴错位）

### 诊断
- 应用用视频自身时间轴做歌词时钟（`findActiveLine(lyrics, v.currentTime)`），不会凭空产生整体偏移。
- 现象=“音频比歌词慢很多”本质是 **LRC 时间轴与该视频对不上**：多半 LRC 与视频来自不同录音/版本；切到伴奏时伴奏常为另一版录音、前奏长度不同，错位更明显。非视频变慢、非程序 bug。
- `lrc.ts` 解析本身正确（支持 [mm:ss.xx]/[mm:ss.xxx]，2位百分秒×10、3位毫秒），且忽略 `offset` 元数据标签。

### 修复（歌词偏移校正 + 按歌曲持久化）
- 确认根因：用户反馈是**官方 MV 自带约 35s 前奏**，LRC 取自曲库音频时间轴 → 歌词整体早 ~35s。典型“LRC 与视频不同源”。
- `src/renderer/player/App.vue`：新增 `lyricOffset` ref（秒，正=歌词延后）；`onTimeUpdate` 改为 `findActiveLine(lyrics, v.currentTime - lyricOffset)`；`nudgeLyric(±0.5/±5, 限幅±120s)` 调整后通过 `setLyricOffset` 回存；`load` 时从 `p.song.lyricOffset` 恢复；keyboard `[`/`←` 提前、`]`/`→` 延后、`Esc` 最小化；面板加 5s/0.5s 粗细两档按钮，样式 `.lyric-offset`/`.grp`。
- `src/shared/types.ts`：Song 加 `lyricOffset: number`；IPC 加 `LYRIC_OFFSET_SET`；KaraokeApi 加 `setLyricOffset(songId, offset)`。
- `src/main/database.ts`：song 表加 `lyric_offset REAL DEFAULT 0`；`initDatabase` 用 `PRAGMA table_info` 检测并为旧库 `ALTER TABLE ADD COLUMN` 迁移；新增 `updateLyricOffset(id, offset)`。
- `src/preload/index.ts`：`setLyricOffset` 调 `IPC.LYRIC_OFFSET_SET`。
- `src/main/index.ts`：import `updateLyricOffset`；注册 `LYRIC_OFFSET_SET` handler 调 `updateLyricOffset`。

### 验证
- `npm run build` 通过（player chunk 10.84 kB）。

### 已知限制

### 数据修正（把偏移烤进 LRC 文件）
- 用户实测「绅士」延迟 15.5s 对齐，要求直接改 LRC 时间戳。
- 曲库/DB 路径：`D:/song-lib/`、`%APPDATA%/local-desktop-karaoke/app-data/karaoke.sqlite`、config.json 同目录。
- 操作：备份 `绅士.lrc` → `绅士.lrc.bak`；每处 `[mm:ss.xx]` += 15.5s（正则 `\[(\d+):(\d+(?:\.\d+)?)\]`）；并把 DB `song.lyric_offset` **清零**（否则会与 LRC 内嵌偏移叠加成双倍）。
- ⚠️ **关键坑**：当把偏移烤进 LRC 时，必须同步把 DB 的 lyric_offset 归零，否则播放时会双重偏移。方向：UI「歌词延后」= 正 offset = 给 LRC 时间戳**加**该秒数。
