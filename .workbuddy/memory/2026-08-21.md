## ⚠️ 关键坑：每个歌目录只能留一个 .lrc
- `src/main/index.ts:215` 启动即 `scanLibrary()` 自动重扫；`scanner.ts:62` 取目录内 `files[0]`（第一个 `.lrc`）。
- 目录里若存在两个 `.lrc`（如 `绅士.lrc` + `orig.lrc`），`files[0]` 顺序不确定 → app 可能读到错误的 LRC，表现就是"歌词没匹配上"。
- `upsertSong` 重扫时**只更新** `lrc_path`，**不动** `lyric_offset`（不会清零）。
- 结论：保证每个歌曲子目录**仅有一个** `.lrc`；备份请改用 `.bak`/`.baked` 等非 `.lrc` 后缀。

- 用户担心 orig.lrc 是 Unix(LF) 而自己用 Windows(CRLF) 导致时间戳不匹配 —— 这是误解。

## 播放模型大改：A/B 切换 → 双音频混音（用户真实需求）
- 用户澄清真实需求：「原唱按钮 = 控制 orig.mp3（人声层）是否输出；伴奏 accomp.mp3 必须一直播放」。
  之前一直做的是二选一（A/B 切换），所以「切到原唱后伴奏没了」——这才是用户反复报"伴奏不出声"的根本语义错位。
- 新架构（src/renderer/player/App.vue 重写）：
  - **两个 `<audio>` 元素**：`accompAudioRef`（伴奏轨，常播）+ `origAudioRef`（人声轨，原唱模式叠加）。
  - `switchMode`：原唱 = accomp 继续播 + orig play；伴奏 = orig pause（accomp 不断）。
  - 音量按轨独立：`accompAudio.volume = accomp×master`、`origAudio.volume = orig×master`。
  - play/pause/seek 同时作用于 video + 两路 audio；onTimeUpdate 对两路音频做 0.3s 漂移校正。
- **修复「切页面/回主控台就暂停」**：
  - 根因：`<video>` 静音（muted）→ 播放窗被盖住/隐藏时 Chromium 暂停静音视频省资源 → 旧代码 onPause 把音频一起停了。
  - 修复：引入 `userPlaying`（用户意图）替代视频状态驱动音频；`onPause` 只在用户暂停时上报/停音频，
    系统隐藏导致的视频暂停不打断音频；`visibilitychange` 可见时把视频拉回音频位置并续播。
  - `windows.ts`：播放窗 webPreferences 加 `backgroundThrottling: false`（被盖住不节流）。
- 验证（CDP 实测）：原唱=双轨同播；切伴奏=accomp 继续、orig 暂停；直接 `video.pause()` 模拟系统暂停后 accomp 仍继续前进。
- 注意点（写进总结给用户）：**orig.mp3 最好是「人声干声」（分离出的 vocals）**，若是完整原曲则原唱模式会叠加两遍伴奏；
  用户目录里的 `poppop.ai - orig_vocals.mp3` 正是人声干声的来源。

## 歌词高亮"没变色"修复
- 现象：用户觉得唱到的歌词和普通歌词颜色差不多、整体没变色。
- 根因（CSS）：`LyricsOverlay.vue` 的 `.cur` 只加了粉色 text-shadow 光晕，**没设置独立 color**，
  文字仍是白色 #fff（和 `.nxt` 一模一样），光晕在白底视频上几乎不可见 → 看起来没高亮。
- 修复：`.cur` 显式 `color: #ff5ca8`（高亮粉）+ 保留深色描边阴影与粉色辉光。
- 验证（CDP 实测）：`.cur` 计算样式 `rgb(255,92,168)` vs `.nxt` `rgb(255,255,255)` 对比明显；
  seek 36s/41s/46s 高亮分别正确推进到第 0/1/2 句（首句 [00:34.27]），音视频同步正常。
  另确认 4~10s 高亮不变是正常的（长前奏 34s 前无歌词，属预期）。

## 副屏待点歌空闲页
- 需求：播完且队列无下一首时，副屏显示「去点歌」提示页而不是黑屏挂上一句歌词；初始化时也要。
- `player/App.vue`：
  - 新增 `idle` ref（默认 true）+ `showIdle()`（清空 current/歌词/视频 src 并 removeAttribute+load 清最后一帧）；
  - `onEnded` 后启动 2.5s 宽限期定时器，期间无新 load 则进空闲态（有下一首时 console 会立刻 playSong 发来 load，被 load() 清除定时器）；
  - 模板 `v-if="idle"` 渲染全屏待机页（🎤 请到控制台点歌 + 渐变暗背景 + 浮动动画），`v-else` 才是原播放内容。
- `main/index.ts`：**启动即创建播放窗**（原为点歌时才建），副屏常驻显示待机页；PLAYER_PLAY 保留创建兜底。
- 验证（CDP 实测）：启动后 idle=true 显示待机页；点歌后 idle=false 正常播放；dispatch ended 事件后 3.5s 回到待机页。

## 曲库目录改版：歌手/歌曲两级结构
- 需求：`D:/song-lib/<歌手>/<歌曲>/`，歌手照片放歌手层（全歌手共享一张），每首歌不再配 artist.txt/artist.jpg。
- `scanner.ts` 重写为两级扫描：
  - 一级目录「含子目录且自身无媒体文件」→ 歌手目录：`findArtistImage(dir)` 取歌手照片，遍历子目录当歌曲；
  - 否则 → 旧平铺布局（兼容）：照旧按歌目录扫，歌手由 artist.txt/LRC [ar:] 推断，照片找歌目录。
  - 抽出 `scanSong(dir, songName, artistFromDir, avatarFromDir, acc)`；歌手优先级：歌手文件夹名 → artist.txt → [ar:]。
- 迁移：`D:/song-lib/绅士 - 双音轨/` → `D:/song-lib/薛之谦/绅士 - 双音轨/`，artist.jpg 上移到 `薛之谦/artist.jpg`，删除歌目录冗余 artist.txt。
- 验证：重扫后 DB 中双音轨 orig/accomp/video 均指向 `薛之谦\绅士 - 双音轨\`，artist=薛之谦（来自文件夹名），
  avatar token 反查 = `D:/song-lib/薛之谦/artist.jpg`（歌手层照片）；旧行被 prune（清理失效 1 行）；旧平铺 `D:/song-lib/绅士/` 仍正常入库。
- 坑：Git Bash 传中文参数给 node 会被转码，导致 sha1 哈希对不上（假阳性）；验证 token 用 `find` 输出的 UTF-8 路径直接喂 node。
